# Creating and editing scripts

1. Call `termous.desktop_workflows.schema` to read the current step contract and limits, then use `termous.desktop_workflows.list` to find existing scripts. The script library is shared locally; identify the script the user means before editing.
2. `termous.desktop_workflows.get` returns the definition for a specified version; `termous.desktop_workflows.versions` returns paginated authorship and version summaries.
3. `termous.desktop_workflows.create` can create an empty draft or a complete definition. `termous.desktop_workflows.update` requires `expected_revision`. To edit steps, supply either a complete `definition` or `changes` keyed by stable step IDs; do not combine them. A complete `definition` also cannot be combined with the separate `parameters` field. Metadata (`name`, `description`, `tags`) and `parameters` can be updated without supplying a definition or step changes. A batch supports at most 64 edits and is atomic: no partial changes are saved on failure. For a move, index is the destination index after the original item has been removed.
   Use the latest script revision for `expected_revision`; a historical run's version may be older. Only a successful mutation response establishes that a new revision was saved. Describing an intended change or calling `runs.start` does not modify the script. A later authorized execution must pin the revision actually returned by the mutation and use a new execution request ID, after checking the previous run's effects. For an uncertain mutation response, retry the identical mutation with its original ID.
4. For `termous.desktop_workflows.duplicate`, specify the source version and a new name. For `termous.desktop_workflows.restore`, specify the historical version and the expected current revision; restoration creates a new version. Editing does not replace the original creator's identity.
5. `termous.desktop_workflows.validate` checks the complete definition. Parameter types are string, number, and boolean. Supply sensitive text only at run start; do not store it in defaults, step text, or descriptions.
6. `termous.desktop_workflows.delete` requires the corresponding permission and follows the current Termous approval policy. Deletion preserves existing reports. On conflict, read the latest version instead of overwriting automatically.

Editing scripts and confirming templates do not require manual approval, but this does not authorize remote input. Use a new `client_request_id` for each logical mutation. If delivery is uncertain, retry with the same ID and identical arguments; do not replay the mutation under a different ID.
